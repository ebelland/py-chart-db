P1-1  [DONE] series operations: declarative parameter spec
      The eight operations run 775-1705 lines each, ~10,000 lines total,
      against a 964-line base. Most of it is form building, signal wiring
      and state persistence repeated eight times. Let an operation declare
      its parameters as data and have the base build the UI:

          PARAMS = (
              FloatParam("window", label="Window", default=11,
                         range=(3, 501), odd_only=True),
              ChoiceParam("mode", label="Method", choices=(...)),
          )

      Built as parameter_spec.py (plain data, no Qt) + parameter_form.py
      (the widgets). Outlier converted as proof.
      CORRECTION to the estimate above: it did NOT collapse the file. Outlier
      went 790 -> 794 lines. For a three-parameter dialog a declaration with
      tooltips and visibility rules costs about what the imperative version
      cost. The gain is in the invariants - visibility rules and widgets are
      the same data so they cannot drift, a parameter cannot be added without
      its signal connection, values() always returns every declared name, and
      odd-window rounding happens in one place. Judge the remaining seven
      conversions on that, not on line count.

N-1   [DONE] series operation: control charts (JMP-style)
      app/series_operations/series_control_chart_dialog.py. Individuals
      (I-MR), moving range, X-bar & R, X-bar & S, with the Nelson run rules.
      The one thing not to "simplify" later: sigma is estimated from
      WITHIN-subgroup variation - average moving range over d2, or average
      within-subgroup range/s - never from the standard deviation of all the
      data. A process that drifted has a large overall SD *because* it
      drifted, so limits built from it swallow the drift and the chart says
      the process is fine. Measured on a +6 sigma shift: overall SD 3.12,
      within-sigma 0.95, 38 signals. Using the overall SD would have given 0.
      The SPC constants are tabulated, not computed - d2 and d3 have no
      elementary form and every other tool uses the same table.
      Violations carry every rule a point broke; the rule numbers are
      historical, not a severity ranking, so reporting only the lowest hid
      rule 7 behind rule 2.
      NOT covered: attribute charts (p, np, c, u). They need counts and a
      sample size per point rather than a measurement, so they want their own
      role mapping - a separate piece of work, not a model to bolt on.

N-2   [DONE] series operation: plot functions without fitting
      app/series_operations/series_function_dialog.py. Same FunctionScanner
      the fit dialog uses, so all 56 functions across 10 categories are
      available and a class dropped into user_functions.py appears with no
      registration. Range as from/to/points/spacing (linear or log), function
      parameters in an editable table, no optimiser.
      It reads no source series and generates one, so it overrides
      selected_series() to return []; _run_operation resolves the target from
      the selected axis, which is unaffected.

N-2b  [DONE] Calculus: draw on a new axis by default
      A derivative divides by dx and an integral accumulates, so neither
      shares a scale with its source - overlaid, one of the two is a flat
      line on the zero gridline. "Draw on a new axis" is on by default, with
      a checkbox to overlay when the ranges happen to be comparable. The axis
      is created once and reused, labelled dy/dx, d2y/dx2 or the integral
      sign from the result rather than from the model name, and removed again
      if the dialog closes without Apply.
      Found while doing this: PARAMS labels and tooltips are class data, so
      the _() sweep never saw them and 47 strings across the new operations
      would have shipped in English with nothing failing. There is now a test
      that discovers every operation's PARAMS rather than hand-listing them,
      so the next operation is covered the day it is written. This closes the
      gap left open under P2-14 for parameters; renderer/operation
      Description attributes are still open.

N-2c  [DONE] operation dialogs: figure locked, series hidden where unused,
      and a new-figure destination
      - The Figure combo is disabled in every operation. It was a live bug,
        not just clutter: a dialog is constructed with one figure_id and
        create_result_axis writes to it, so changing the combo listed one
        figure's axes while the results went to another's. Disabled rather
        than hidden - which figure is being operated on is worth seeing.
      - Function hides the series list (SHOWS_SERIES_SELECTOR = False); it
        generates a series rather than reading one. Figure and axis rows stay,
        because a generated curve still has to be drawn somewhere.
      - Calculus's new-axis checkbox became a three-way choice: new axis in
        this figure (default), same axis, or new figure. create_result_figure
        is on the base for any operation to use.
      Found while doing this: _open_series_operation reloaded the panel but
      never the tabs, so a figure created by an operation stayed invisible
      until restart.

N-1b  [DONE] control charts: draw the centre line, limits and zones
      Four checkboxes in the parameters - centre line, control limits, the one
      and two sigma lines, and highlighting the flagged points. Limits and
      centre default on: without them the chart is a run chart, which shows
      the same numbers and answers a different question.
      Needed a base change: result_series_specs() (plural) alongside the
      existing singular hook, defaulting to one so nothing else moved. Both
      preview and apply iterate it, so a line is previewed, cleaned up and
      applied on exactly the same path as the data.
      All the lines are columns of the one result table and every series is a
      plain "SELECT x, <column> AS y", so the renderer needs no special case
      and switching a line on later is a descriptor change, not a
      recomputation. The flagged points get a violation_y column that is NULL
      elsewhere, so they draw alone without a second table.

N-3   attribute control charts (p, np, c, u)
      The half of SPC N-1 does not cover. These plot a proportion or a count
      rather than a measurement, so the limits are binomial/Poisson rather
      than normal, and the limits vary per point when the sample size does.
      Needs a "sample size" role alongside x and y, which is the real work.
