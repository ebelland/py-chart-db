N-4   Gridded-data renderers
      [CONTOUR half is DONE: app/charts/contour.py. ContourAxisRenderer
      (contourf/contour) pivots x/y/z rows into a grid;
      ContourScatteredAxisRenderer (tricontourf/tricontour) triangulates the
      raw points, so the map covers the hull of what was measured and stops
      there - griddata was the other option and was not taken, because a grid
      fills the corners with numbers that look like measurements.
      The grid check itself moved to app/charts/grids.pivot_to_grid and is
      now shared with the surface renderers rather than duplicated;
      finite_xyz is the scattered half, shared the same way. The two new
      categories put "Gridded data" and "Irregularly gridded data" in the
      chart picker for the first time. Demo project "Contour maps - the same
      fields drawn flat" reuses the wafer and survey tables, so the surface
      and contour readings of one dataset sit side by side.
      Found on the way: a colorbar built while the layout engine is still
      "none" - which is when every renderer draws - makes a gridspec with
      zero-height rows, and a constrained engine applied afterwards divides
      by it and the figure will not draw at all. contour.py's _colorbar
      passes use_gridspec=False for that reason; regression test in
      test_contour_axis.py. Any future renderer that adds a colorbar needs
      the same, or the pipeline needs to set the layout engine before the
      renderers run instead of after.]
      What is left is the rest of the "Gridded data" family, per
      matplotlib.org/stable/plot_types: pcolormesh, imshow/matshow and the
      streamplot/quiver family on a regular grid - the same "is this actually
      a grid" decision, which now has one implementation to call.
      Pairs with the heatmap/imshow line under P2-1.

N-5   sqlite_repo: 3013 lines in one module
      Split by subject rather than by size - connection and pragmas, tables

      cache belong with the connection, not with the descriptors.

N-6   icons: finish the SFSymbol / Segoe Fluent migration
      This is P0-7 plus the rest of it: seven of the failing tests are the

      with no common fallback, and icon files nothing asks for any more.

N-8   ChartPanel: "Add vertical line" / "Add horizontal line"
      Same context menu, with a small dialog for the line style, persisted in
      the axis options like the annotations are - so they survive a reload and
      can be edited from the properties panel afterwards. A new options key
      ("lines") drawn by the base renderer beside apply_annotations.

N-9   documentation
      docs/DEVELOPMENT.md is behind the renames, the fit rework and the new
      startup path; and there is no user manual at all. The manual should be

      cannot drift.

N-3   attribute control charts (p, np, c, u)
      The half of SPC N-1 does not cover. These plot a proportion or a count
      rather than a measurement, so the limits are binomial/Poisson rather
      than normal, and the limits vary per point when the sample size does.
      Needs a "sample size" role alongside x and y, which is the real work.

      Preserves visual shape at a fraction of the draw cost.
      PROMOTED IN VALUE by the P1-2 measurements: with blitting in place the
      repaint is flat at ~2.55ms, so the hover hit test is now the dominant
      cost at scale - 4.63ms of a 7.21ms budget at 500k points. Downsampling
      shrinks the hit test and the draw together. This is the next
      interactivity item worth doing.
